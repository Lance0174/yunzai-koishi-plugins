# 0.2.0 整改与验收记录

日期：2026-09-12。三个独立插件：群管理、点歌、仅 B站/抖音/小红书的视频解析。

## 用户问题与本次结果

- 视频默认 autoParse=true；直接发送三站链接、BV 或 QQ JSON 分享卡片即可解析，不需要 Koishi 的全局指令前缀。空 groups 适用插件作用范围内的群与私聊；排队/任务编号提示默认关闭。显式旧配置 autoParse=false 需要在升级时改成 true。
- 禁言、踢人、全员禁言直接执行，移除“群管理 执行”确认指令；保留实时角色/范围校验、审计和处罚豁免。常用群管提供短命令。批量潜水踢人仍提供预览和 --执行 参数。
- 点歌移除下载子命令和群文件上传；默认音乐卡片，可显式选择卡片/语音或回复序号选歌。网易云、QQ 原生卡片使用歌曲 ID，发送卡片无需先取得可播放音源。
- 群管理增加：管理员/头衔、群名/头像、公告/精华、成员/禁言列表、批量解禁、发言/潜水/入群排行及潜水清理、定时禁言/解禁、自闭、豁免/申请黑名单、违禁词、投票禁言/踢人、入群验证码、自动邀请/申请策略、群通知、文本转发/撤回恢复、群列表/手动退群、群荣誉/打卡、历史申请查询和有 flag 的补录。

源码是独立实现，没有复制参考库实现后改许可证。网络检查工具是套件自身已有代码的独立副本，三个包不相互依赖。旧版开发与公开源站测试记录保留在 docs/history/DEVELOPMENT-0.1.0.md。

## 协议与持久化边界

固定 SnowLuma 提交 fb5f9b21558134db8803d216dfc19c6bce11f2c0：group-admin.ts、group-info.ts、extended.ts，以及核心 web.ts 的公告映射。已检查公告、精华、禁言字段和打卡接口真实调用路径；匿名开关/匿名禁言为空实现，继续排除。静态接口存在不等于用户服务器已兼容。

OneBot 适配器把短数值 *_id 参数转成数字；SnowLuma 删除公告要求字符串，因此此动作通过适配器 _get 传递原始 notice_id。其他动作使用已声明的官方适配器方法。历史请求只使用真实 flag，不把 request_id 拼装成可操作标识。

定时、投票、验证、名单、活动计数和路由状态共用原 Store 的进程内串行事务。每次执行保存唯一认领标识，最终状态与审计同事务；中断、超时或连接异常记未知，不自动重试。仅验证单进程 sql.js SQLite；不声明多进程共享文件支持。

正文路由默认关闭；开启后按明确来源/通知目标、保留期限和每群 1000 条上限保存文本。关闭即清空对应缓存。缓存不含图片/文件。自动规则重查当前角色；旧处理结果不能覆盖新一轮任务。撤回成功后禁言失败记录为未全部确认，不伪报整组动作成功。

本轮未实现：G20 周期按人数自动退群；G22 自动反禁言/退群拉黑；G24 图片文件转发/恢复；A06 幸运字符/星级/网页历史统计；音乐推荐/云盘/账号扫码和视频评论卡片。功能覆盖清单明确保留部分实现状态。

| SQLite 报 cannot modify primary key，导致定时/投票/验证码测试失败 | 更新对象排除 id；新增事务、并发和重启测试，回归通过 |

| 验证测试被异步欢迎通知抢先匹配、头衔测试忽略了违禁词会先撤回 | 按正确消息种类验收；覆盖阻断效果，不删除已有词语保护 |
| 添加路由权限复核后出现 undefined 不能赋给 DataRow 的编译错误 | State.get 明确返回 DataRow 或 undefined，完整回归通过 |

| 匿名 GitHub tree HTTP 403，gh tree EOF | 改用固定提交 codeload ZIP 只读检查，成功取得完整快照；不分发上游源码 |
| 安装包独立加载退出时，自动群管后台任务与数据库关闭发生竞态告警 | 跟踪并等待插件后台任务，停止后不启动新任务，无 Bot 时不启动自动调度；重新打包验收 |
