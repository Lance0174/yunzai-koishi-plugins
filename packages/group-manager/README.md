# Ember 群管理

Koishi 4.18.11 + 官方 OneBot v11 适配器。需要 `database` 服务。审核、通知、群管三个模块可分别关闭。

## 配置与权限

- `reviewers`：允许审核请求的 QQ 号。
- `reviewGroups`：接收请求/事件通知、允许编号或引用审核的群号。
- `managedGroups`：开放基础群管、采集群事件的群号。留空不开放群管。
- `botIds`：限定机器人 QQ；留空允许所有 OneBot 账户，数据仍按账户隔离。
- `privateReview`：允许审核人私聊用请求编号审核，默认关闭。
- `inviteAllow` / `inviteDeny`：机器人加入群的允许/拒绝名单。留空允许名单不限制目标；命中拒绝名单不能同意。始终人工审批。

审核机器人邀请必须是配置的审核人且处于允许的审核会话。审核成员申请还要实时确认操作者和 Bot 在目标群有管理权限。普通群管要求操作者及 Bot 均有目标群权限，不使用其他群的管理员身份替代。

## 指令

| 指令 | 用途 |
| --- | --- |
| `群管理 请求列表 [页码]` | 按当前 Bot 查看请求及状态 |
| `群管理 审核 R-编号` | 查看一条请求；也可引用原通知 |
| `群管理 同意 R-编号` | 同意请求；引用原通知时可省略编号 |
| `群管理 拒绝 R-编号 --原因 内容` | 拒绝对应请求 |
| `群管理 禁言 @成员 10m` / `群管理 解禁 QQ号` | 修改禁言，支持 s/m/h/d 和中文单位 |
| `群管理 全员禁言 开` / `关` | 开启须二次确认，关闭直接提交 |
| `群管理 踢人 @成员` | 生成操作预览和 60 秒确认码 |
| `群管理 执行 确认码` | 由原操作者在原群确认一次操作 |
| `群管理 名片 @成员 新名片` | 修改后回读确认 |
| 引用消息后 `群管理 撤回` | 查询并确认消息属于当前群后撤回 |
| `群管理 审计 [页码]` / `诊断` | 查看操作状态、Bot 和协议端版本 |

时长范围 1 秒～30 天，QQ 号与 @ 均可使用。群主、受保护管理员和机器人自身不能被越权处理。

## 持久化与恢复

请求按 Bot、请求类型、原始 flag 去重，审核回传原始 flag。引用审核绑定实际发送成功的通知消息 ID 和会话，不读取引用正文猜测请求。

已验证 SQLite 4.7.0 在**单个 Koishi 进程**中的并发认领、事务回滚和重启恢复。插件用事务内认领+审计，并串行执行自身状态写入。不要让多个 Koishi 进程共享 sql.js 的 SQLite 文件；其他驱动和多进程部署未验收。

待审核状态可以在重启后继续处理；执行中断、动作超时或响应丢失标记“结果待核实”，不会自动重复审批。平台明确拒绝记录失败。平台返回 ok 只表示收到成功响应，仍应核对群内效果。

事件通知包括成员/Bot 进退群、角色、禁言和撤回元数据，不保存撤回正文。每目的地最多保留 100 条详细待发事件，更多事件合并为数量摘要；每批最多 10 条，默认发送间隔 1500ms。通知队列持久化，结果未知不自动重发；已结束事件记录保留 7 天。操作审计默认保留 30 天。请求通知丢失时可以从请求列表处理。

## 首版范围

面向 SnowLuma 的标准动作已通过官方适配器模拟协议测试，真实服务器/QQ 效果待验收。没有启用自动同意、验证码、违禁词、公告、精华、头衔、匿名管理、批量踢人或自动退群。
