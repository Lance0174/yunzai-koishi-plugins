# Yunzai 群管理迁移 0.3.0

功能来源：[yenai-plugin](https://github.com/yeyang52/yenai-plugin)（yeyang52 / yeyang 及贡献者）、[GroupEntry_Plugin](https://github.com/A1Panda/GroupEntry_Plugin)（A1Panda / @A1_Panda 及贡献者）。感谢原作者；这是 Koishi 迁移实现，作者、对应模块与许可见 [THIRD_PARTY_NOTICES.md](THIRD_PARTY_NOTICES.md)。

包名 `koishi-plugin-yunzai-group-manager`，插件键 `yunzai-group-manager`。适用于 Koishi 4.18.11、官方 OneBot v11 适配器和 SnowLuma，需要 database 服务。

## 配置和日常使用

日常群管默认在所有群可用，不要求逐群填写允许名单；实际操作仍检查操作者和机器人的群角色。reviewers 填写机器人管理员 QQ，reviewGroups 只用于请求审核，不再兼作事件监听收件人。botIds 可限定机器人 QQ，数据按账户和群隔离。旧 managedGroups 仅保留隐藏兼容，升级脚本会移除此旧限制。

shortcuts 默认开启，下表短指令可直接使用；Koishi 自己设置的全局指令前缀仍适用。也可用完整指令，例如“群管理 禁言 @成员 10m”。禁言、踢人、全员禁言直接执行，不需要二次确认码。批量潜水清理提供预览和 --执行 参数。

日常管理实时检查操作者、机器人和目标的群角色。设置管理员/头衔要求机器人为群主，操作者为具有群管理权限的配置审核人。全部群管命令默认注册；投票处罚默认 3 票、5 分钟，成员自助头衔默认可用，入群验证默认 5 分钟且超时不踢人。可用对应指令调整参数或关闭。违禁词和定时任务需要管理员实际添加规则；自动同意申请需要匹配条件，不能随意编造默认答案。reviews、moderation 的旧模块开关不影响独立事件监听。

| 指令 | 效果 |
| --- | --- |
| `禁言 @成员 10m` / `解禁 @成员` | 一名成员禁言/解禁，支持 QQ 号及 @ |
| `踢人 @成员 [--拉黑]` | 直接移出成员，默认允许再次申请 |
| `全员禁言 开` / `全员禁言 关` | 直接切换全员禁言 |
| `名片 @成员 新名片` | 修改群名片，并回读确认 |
| 引用消息后 `撤回` | 验证引用属于当前群后撤回 |
| `设置管理 @成员` / `取消管理 @成员` | 授予/撤销管理员，并回读 |
| `设置头衔 @成员 新头衔` / `清除头衔 @成员` | 设置/清空头衔 |
| `群管理 开放头衔 开或关` / `申请头衔 新头衔` | 可选成员自助头衔，受违禁词约束 |
| `修改群名 新名称` | 修改群名，并回读 |
| 发送图片或引用图片后 `设置群头像` | 只读取 avatarHosts 域名的图片，最大 5MB |
| `群公告 正文` / `公告列表 [页码]` / `删除公告 编号` | 发布、查看、删除本群公告 |
| 引用消息后 `加精` / `移精`，`精华列表 [页码]` | 添加、移除、查看精华 |
| `群成员 QQ号` | 查询角色、头衔、入群与最近发言时间 |
| `禁言列表 [页码]` / `解除全部禁言` | 查询禁言；逐个解禁，最多 100 人，分别报告结果 |
| `活跃排行 [页码]` / `潜水排行 [页码]` / `最近入群 [页码]` | 本地累计发言、最近发言和入群时间排序 |
| `清理潜水 30 [--执行]` | 超过 30 天未发言且入群超过 30 天的普通成员；执行时重新核验，最多 30 人 |
| `我要自闭 10m` | 普通成员只能禁言自己，每分钟一次 |
| `发通知 群号,群号 正文` | 最多 10 个可管理群，逐群核验角色、限速并报告 |
| `群列表 [页码]` / `机器人退群 当前群号` | 管理范围内的群；退群只允许配置审核人，不解散群 |
| `群荣誉 [all/talkative/performer/legend/strong_newbie/emotion]` | 协议提供的群荣誉 |
| `群打卡列表` | 群今日打卡名单 |
| `群管帮助` / `群管理 审计 [页码]` / `群管理 诊断` | 完整提示、操作记录、协议版本 |

时长支持 30s、10m、2h、1d 和中文单位，范围 1 秒～30 天。缺少发言/入群时间不会被当成“从未发言”而踢人。活跃排行只统计插件实际收到的消息，不等于 QQ 网页历史统计。管理员和豁免成员不会被自动投票/词语/验证码处罚。

## 黑白名单与独立监听

```text
黑名单 添加 @成员
黑名单 删除 @成员
黑名单 列表
黑名单 添加 QQ --全局
黑名单 添加 群号 --群
白名单 添加 @成员
白名单 添加 QQ --全局
白名单 添加 群号 --群
事件监听 状态
事件监听 开 --管理员
事件监听 开 --群 888888 --私聊 100001
事件监听 关
事件通知 状态
事件通知 关 成员变动
事件通知 开 成员变动
事件通知 关 全部 --全局
```

黑名单消息被忽略，不回复指令、不转发正文，也不自动踢人；白名单豁免本插件的成员禁言、踢人、违禁词处罚、投票和入群验证，不提升操作权限。黑白名单重复时黑名单优先。默认维护当前群成员名单；`--全局` 和 `--群` 仅机器人管理员可修改，支持私聊管理。`豁免` 保留为旧成员白名单指令，申请黑名单仍是独立审核规则。

事件监听 `listener` 默认开启，独立于群管理与请求审核。`listenerMode: admins` 默认私聊 reviewers；`custom` 则向 listenerTargets 配置的群聊/私聊发送，可以同时配置多个目的地。事件通知默认开启，支持群聊变动、成员变动、管理员变动、禁言、撤回、好友变动、好友申请、群邀请和入群申请；通过指令分别或全部开关，开关写入数据库，重启保留。群内指令默认只改本群；私聊或 `--全局` 修改当前机器人默认设置。

普通群消息/私聊正文转发单独用 `事件通知 开 群消息 --全局`、`事件通知 开 私聊消息 --全局` 开启，默认不转发聊天正文。消息中的非文本元素以类型提示呈现；原始图片/文件恢复仍未迁移。监听目标不需要列入 reviewGroups 或 managedGroups；关闭或变更目的地后，旧队列不会转投到新收件人。

未配置 reviewers 或自定义目标时仍可执行群管，监听没有可投递收件人；使用“事件监听 状态”可查看。QQ 的全员禁言是群设置，无法为个别普通成员单独豁免。

## 定时任务和自动规则

| 指令 | 用法 |
| --- | --- |
| `定时禁言 10m [@成员 30m]` | 10 分钟后禁言；省略成员则开启全员禁言 |
| `定时解禁 10m [@成员]` | 10 分钟后解禁；省略成员则关闭全员禁言 |
| `定时任务` / `取消定时 编号` | 查看状态和取消尚未执行任务 |
| `豁免 添加/删除/列表 [QQ]` | 处罚豁免名单；不限制管理员解除禁言 |
| `申请黑名单 添加/删除/列表 [QQ]` | 独立申请黑名单；人工同意前也要移除名单 |
| `违禁词 添加 词语 [--精确] [--禁言 10m]` | 默认包含匹配并撤回，可附加禁言；含空格词语用引号 |
| `违禁词 删除 词语` / `违禁词 列表` / `违禁词 预览 "文本"` | 管理/预览规则，不运行正则表达式 |
| `投票设置 开 --票数 3 --期限 5m` / `投票设置 关` | 2～50 票通过，期限最多 1 小时 |
| `投票禁言 @成员 10m` / `投票踢人 @成员` | 默认开放群成员发起，发起人计一票 |
| `赞成 编号` / `投票列表` / `取消投票 编号` | 一人一票；取消仅限管理员 |
| `入群验证 开 --超时 10m [--踢出]` / `入群验证 关` | 验证码，默认超时只通知管理员；--踢出 才移出 |
| `验证 六位验证码` / `验证通过 @成员` | 本人验证或管理员豁免待处理任务 |
| `自动审核 开 --答案 "答案一或答案二" [--包含] [--等级 10]` / `自动审核 关` | 名单拒绝、答案匹配同意；多答案以竖线分隔，无同意条件时保留人工审核 |
| `群管理 审核预览 "申请备注"` | 只预览答案，不处理申请 |
| `群管理 消息路由 开 --目标 通知群号 --转发 --撤回 --保留 30` | 显式文本转发/撤回恢复，单位分钟，最多 1440 分钟、每群 1000 条 |
| `群管理 消息路由 关` | 关闭并删除本群正文缓存 |

定时支持相对时长或带时区的 ISO 时间，例如 `定时禁言 2026-10-01T22:00:00+08:00`。列表显示 UTC 时间。任务保存到数据库，重启继续，执行时重新检查权限、名单、策略。已开始执行的任务不能当作未执行任务取消；中断或丢失响应不自动重试。

等级只使用申请事件明确提供的数值 level。协议未提供时保留人工审核，不当成 0，也不把群活跃等级当 QQ 等级。验证码未确认送达时不执行超时处罚。关闭验证、豁免或管理员通过验证可阻止尚未执行的处罚。已完成的踢出无法自动撤销；解禁使用普通解禁命令。

## 请求审核

`群管理 请求列表 [页码]`、`群管理 审核 R-编号`、`群管理 同意 R-编号`、`群管理 拒绝 R-编号 --原因 内容`。引用原通知可省略编号，只按真实消息 ID 定位，不从引用正文猜测。

privateReview 默认开启，审核人可私聊使用请求编号。inviteAllow / inviteDeny 控制机器人接受的群邀请；autoInvite 默认关闭，显式打开后只自动接受 inviteAllow 明确列出的群，拒绝名单优先。

`群管理 历史申请` 查看协议端保留的申请。`群管理 补录申请` 只接受明确提供原始 flag、群和申请人的未处理条目，与实时请求共用去重。只有 request_id 而没有 flag 的条目仅供查看。

## 存储与验收

在 Koishi 4.18.11、官方适配器 6.9.4、单进程 SQLite 4.7.0 下通过协议测试、并发认领和重启恢复。尚未连接用户的真实 SnowLuma 服务器；成功响应不等于已验证 QQ 客户端效果。

状态写入共用进程内串行事务；执行状态与审计一同保存，旧执行结果不能覆盖新任务。只验证单 Koishi 进程，勿让多个进程共享 sql.js 文件。

通知默认每 1500ms 一批、每批最多 10 条；每目的地最多 100 条详细待发事件，超出合并数量。发送未知不重试。事件保留 7 天，审计和结束任务默认保留 30 天。正文默认不缓存，开启后只保存受限文本，不恢复图片/文件。

尚未实现按人数周期自动退群、退群自动拉黑/自动反禁言、幸运字符/星级/网页统计。匿名操作因固定 SnowLuma 源码为空实现而不提供。
